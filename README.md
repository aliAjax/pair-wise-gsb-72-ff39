# 功能开关灰度发布与影响审阅平台

基于 React 的本地可运行前端工程，覆盖功能开关配置、影响评审、依赖分析、灰度时间线、冻结回滚和发布报告。业务数据由 RTK Query 端点驱动，并持久化到浏览器 `localStorage`。

## 技术栈

- React 18 + TypeScript + Vite
- MUI
- Redux Toolkit
- RTK Query
- React Router

## 启动

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:18472`。

## 构建

```bash
npm run build
npm run preview
```

## 工作区

- 发布概览：开关采用趋势、环境放量差异、阻断问题和待评审项
- 功能开关：按状态、环境、团队和关键字筛选，进入完整配置编辑器
- 影响评审：逐项检查规则冲突、死代码、指标缺失、实验重叠和客户端兼容
- 依赖关系：依赖影响图、互斥冲突矩阵和降级关系
- 灰度发布：分阶段放量、环境差异、指标守护、冻结和紧急回滚
- 发布批次：把同一开关的多环境发布收成一个批次，逐环境生成不可变候选，按开发 → 预发 → 生产顺序放行
- 审计与回滚：查询调整、审批和异常事件，记录受影响用户范围
- 发布报告：查看发布明细并导出 CSV

浏览器首次打开时会自动写入示例数据。编辑、审批、灰度和回滚操作会写入 `feature-flag-release-console-v2` 对应的本地存储键。

## 发布批次规则

- 从选中环境生成**不可变候选**，候选只保留四要素：受众规则、依赖开关、来源环境最低客户端版本、灰度阶段（含比例）。
- 候选**确认前**来源环境四要素任一变化，候选立即失效，需要重新生成；确认后的漂移在执行时由 `stale-source` 门禁拦截。
- 两个窗口同时为同一开关提交批次时，只保留既有进行中批次，第二次提交写入 `batch-superseded` 审计。
- 执行时按环境顺序逐环境门禁校验：依赖被回滚/未启用、最低客户端版本高于环境在线基线、或缺少上游环境放量记录时**整批停止**，已写入环境保持候选值。
- 写入失败只把当前候选标记为 `failed` 并保留未完成项，不落盘部分写入；修复后从断点重试。
- **整批回滚**只恢复候选恢复点中的受众、依赖和灰度阶段（发布时新建的目标记录会移除），最低客户端版本和开关状态等发布后字段保持不变，原审批与发布审计仍可查询。
- 页面顶部可调整各环境在线客户端版本基线，并可注入下一次写入失败用于演示重试路径。

## 测试

```bash
npm run test:batches
```

端到端逻辑测试覆盖候选失效与重生、重复提交去重、依赖回滚/版本不满足/环境顺序三种整批停止、写入失败断点重试、整批回滚恢复边界等 36 项断言。
